BAO CAO KIEN TRUC MATCHMAKING PRODUCTION - CHESS ARENA
Ngay cap nhat: 27/05/2026
Pham vi: Quick match 1v1, friend challenge, rematch, realtime chess web

======================================================================
A. NHAN XET TONG QUAN
======================================================================

1. Ket luan

Phien ban cu du cho MVP nhung khong du production vi match duoc thuc hien bang
nhieu DB call roi rac o API JavaScript. Phien ban moi trong code da dua quyet
dinh quick match vao PostgreSQL RPC transactional:

- public.quick_match_find_game(...)
- public.quick_match_cancel(...)
- public.cleanup_online_matchmaking()
- trigger public.enforce_single_active_online_game()

API Next.js van lam auth, validation, rate limit va dinh dang response.
PostgreSQL lam phan bat buoc atomic: ticket, lock, chon opponent, tao game,
mark matched, presence va audit event.

2. Phan da trien khai trong code

- Queue ticket co id rieng, status, mode, pool, rating window, client/session,
  timestamps va lien ket game.
- FIFO khong bi heartbeat lam moi: joined_at bat bien khi dang waiting.
- Liveness tach rieng bang last_seen.
- Rating theo mode: bullet, blitz, rapid, classical.
- Rating window mo rong theo thoi gian cho.
- SELECT FOR UPDATE SKIP LOCKED trong RPC.
- Trigger ngan mot user co nhieu game active, ap dung ca quick/friend/rematch.
- Bang online_game_tickets ngan mot ticket duoc dung lai boi RPC.
- Trust pool va abuse/audit tables lam diem tich hop cho fair play.
- Cancel spam cooldown co ban.
- API /find, /cancel, /status.
- Maintenance RPC va view metrics theo gio.

3. Viec bat buoc truoc khi thu nghiem

Can chay noi dung backend/supabase/schema.sql tren Supabase database.
Backend moi se khong tu dong quay ve thuat toan cu neu RPC chua ton tai, vi
fallback nhu vay lam mat bao dam race-condition cua production.

======================================================================
B. DANH GIA HE THONG VA RUI RO
======================================================================

Da dung:
- Firebase session cookie duoc kiem tra o backend; client khong gui user_id.
- time_control duoc validate.
- joined_at va last_seen da duoc tach nghia.
- realtime move khong phu thuoc heartbeat.

MVP:
- Luong cu du MVP quy mo nho.
- Luong RPC moi la nen tang dung de tien toi production, nhung can migration,
  integration tests va load tests truoc khi cong bo scale.

Khong nen tuyen bo con so user toi da khi chua load test tren Supabase project
that. Gioi han phu thuoc tier DB, connection pool, Realtime fanout, index,
traffic theo time-control va latency khu vuc.

Rui ro nghiem trong neu khong dung RPC/constraint:
- Duplicate game do hai backend instance cung claim opponent.
- Mot user co nhieu active game do quick/friend/rematch chay dong thoi.
- Match voi ticket stale.
- Mat audit trail vi xoa ticket thay vi mark trang thai.

Bao dam phien ban moi:
- Ticket waiting/claimed cua mot user duoc gioi han bang partial unique index.
- Mot ticket da gan game co ban ghi online_game_tickets primary key.
- Trigger database khoa hai user va chan active game trung.
- Opponent selection lock row va skip ticket dang duoc transaction khac xu ly.

======================================================================
C. SCHEMA PRODUCTION DA BO SUNG
======================================================================

1. online_match_queue

Cot cot loi:
- id uuid primary key: ticket bat bien de audit va tham chieu game.
- user_id uuid: nguoi xep hang.
- time_control text: pool thoi gian cu the, vi du 180+0, 600+0.
- mode text: bullet/blitz/rapid/classical, dung cho rating rieng.
- rating integer: snapshot rating khi tim.
- rating_min/rating_max integer: window hien thi/audit tai thoi diem cap nhat.
- rating_range_preference integer: gioi han nguoi choi cho phep.
- pool text: standard/provisional/low_trust/restricted.
- status text: waiting/claimed/matched/cancelled/stale.
- joined_at: FIFO, khong lam moi bang heartbeat.
- last_seen: liveness ticket, duoc heartbeat cap nhat.
- claimed_by/claimed_at/matched_game_id: trace ket qua claim.
- cancelled_at/cancel_reason: audit huy/stale.
- client_id/session_id/region/latency_ms: trace tab, device, latency.

Index/constraint:
- primary key id.
- unique partial (user_id) where status in ('waiting','claimed').
- index (time_control, mode, pool, joined_at, rating) where status='waiting'.
- index last_seen where status in ('waiting','claimed').
- FK matched_game_id.
- check status/mode/pool/rating bounds.

2. online_presence

Presence khong phai queue. Presence tra loi "client con song/choi game nao";
queue tra loi "ticket nao dang duoc xet ghep".

Cot moi:
- current_queue_ticket_id: lien ket ticket hien tai.
- client_id/session_id: phan biet tab va trace ket noi.
- current_game_id/status/last_seen: trang thai truc tuyen.

3. online_games

Cot matchmaking moi:
- mode, rated, started_at, finished_at.
- white_rating_before/black_rating_before.
- white_rating_after/black_rating_after.
- matchmaking_ticket_white/matchmaking_ticket_black.
- matchmaking_pool, rating_gap.
- match_wait_time_white/match_wait_time_black.

Bao dam:
- check white_user_id <> black_user_id.
- online_game_tickets(ticket_id primary key) ngan reuse ticket.
- trigger enforce_single_active_online_game chan user co game active trung,
  bat ke game duoc tao boi route quick, friend hay rematch.

4. Bang phu

- user_ratings: rating rieng theo mode, provisional, deviation, volatility.
- user_trust_scores: pool va cac signal fair-play; da tao schema, chua tu
  dong ket toi AI anti-cheat.
- user_matchmaking_stats: finds/cancels/aborts/cooldown.
- matchmaking_events: event trace va metrics.
- matchmaking_claim_logs: dieu tra claim/race.
- matchmaking_abuse_logs: cooldown block va signal abuse.
- user_active_locks: audit lock game active; trigger la bao dam cuoi cung.

======================================================================
D. RPC TRANSACTIONAL VA RACE CONDITION
======================================================================

RPC: public.quick_match_find_game(
  p_user_id, p_time_control, p_mode, p_rating,
  p_client_id, p_session_id, p_region, p_rating_range_preference
)

Quy trinh trong mot transaction:
1. Validate time control va mode.
2. Doc user tu database; khong tin display/rating tu client.
3. Lay advisory lock namespace queue theo user de chan hai tab tao ticket cung luc.
4. Neu user da co active game, tra game do de reconnect.
5. Lay rating server-side tu user_ratings(mode); p_rating khong duoc dung lam authority.
6. Lay pool tu user_trust_scores; restricted bi tu choi.
7. Kiem tra cooldown huy queue.
8. Khoa ticket hien tai cua user. Neu cung tham so va waiting thi giu joined_at;
   neu tham so doi thi cancel ticket cu va tao ticket id moi.
9. Upsert presence status=queue.
10. Mark ticket stale neu last_seen het han.
11. Tim opponent cung time_control/mode/pool, live, khac user, rating hop le
    hai chieu; uu tien rating gap nho roi FIFO.
12. SELECT FOR UPDATE SKIP LOCKED opponent ticket.
13. Insert online_games trong transaction; trigger khoa hai user theo thu tu
    co dinh va tu choi neu mot ben co active game.
14. Insert online_game_tickets, mark hai ticket matched, update presence playing.
15. Ghi claim log va matchmaking_events.
16. Return matched/waiting cung ticket id, rating window va rating gap.

Vi sao FOR UPDATE:
- Hai transaction khong the cung lay mot opponent ticket de tao hai game.

Vi sao SKIP LOCKED:
- Khi mot ticket dang duoc ghep, request khac bo qua ngay de tim ticket khac,
  khong tao hang cho lock lam tang p95 latency.

Neu transaction rollback:
- Game, ticket status, presence va event deu rollback cung nhau.
- Khong co trang thai "ticket matched nhung game khong ton tai".

Vi sao khong dat logic chinh o JavaScript:
- API call roi rac khong atomic tren nhieu instance/serverless.
- DB moi la noi duy nhat co row lock, constraint va transaction chung.

======================================================================
E. RATING MATCHMAKING
======================================================================

Mode:
- bullet: duoi 3 phut.
- blitz: tu 3 phut den duoi 10 phut.
- rapid: tu 10 phut den duoi 60 phut.
- classical: tu 60 phut.

Window da trien khai:
- 0-3 giay: +/-50.
- 3-8 giay: +/-100.
- 8-15 giay: +/-200.
- 15-30 giay: +/-350.
- Tren 30 giay: +/-500.
- Luon bi gioi han boi rating_range_preference cua tung ben.
- Match chi hop le khi window cua ca hai ben chap nhan rating gap.

Quy tac production tiep theo:
- Provisional/new account nen ghep provisional truoc, deviation cao hon.
- Rating cao can window mo rong cham hon de tranh game kem can bang.
- Khong cho preference qua hep duoc dung de farm; can cooldown va theo doi
  repeated-opponent/rating-selection behavior.
- Rating before/after va rating_gap duoc luu tren online_games de audit.

Friend challenge:
- Da danh dau rated=false. Loi moi choi voi ban be khong tac dong ladder.

======================================================================
F. FAIR PLAY, TRUST SCORE VA ANTI-ABUSE
======================================================================

Schema da tao user_trust_scores gom:
- trust_score, pool.
- abort_rate, disconnect_rate, timeout_rate, report_count.
- cheat_suspicion_score, sandbagging_score, smurf_score.

Chinh sach de xuat:
- Khong ban hoac ket toi cong khai chi dua tren mot signal.
- standard va provisional la pool binh thuong.
- low_trust chi dung khi nhieu signal lap lai va co nguong audit.
- restricted dung cho ban/hold duoc xac nhan boi he thong moderation.
- Cho phep trust phuc hoi theo cua so 30 ngay neu hanh vi tot.
- UI chi thong bao matchmaking unavailable/longer wait; khong tiet lo anti-cheat.

Anti-abuse da trien khai:
- Rate limit API.
- Mot waiting/claimed ticket tren moi user.
- Session/client id tu frontend de audit nhieu tab/device.
- Cancel lap lai trong 30 giay tao cooldown tang dan va abuse log.

Can lam tiep:
- Abort penalty sau khi game duoc tao.
- CAPTCHA/friction cho pattern bot.
- Device fingerprint hop phap va chinh sach privacy.
- Signal pipeline cho report/engine similarity/smurf/sandbagging.

======================================================================
G. EDGE CASE VA CACH XU LY
======================================================================

- A dong tab luc match: game da tao van la authority; reconnect bang active game,
  neu khong quay lai thi timeout/abort policy xu ly.
- Hai request cung chon opponent: row lock + SKIP LOCKED.
- Hai tab cung user: advisory queue lock + partial unique active ticket.
- Heartbeat tre: last_seen cua server, khong dung clock client.
- Serverless song song: decision nam trong DB transaction/trigger.
- Game tao xong nhung response mat: /status hoac heartbeat tra active game.
- Ticket matched nhung presence queue: khong xay ra trong RPC; maintenance sua
  drift neu co thao tac legacy/admin.
- Presence playing khong co active game: maintenance va reconnect logic can reset.
- Transaction fail: rollback atomic.
- Realtime delay: GET/status/heartbeat la fallback, snapshot khong duoc lui ply.
- Session het han: API tra 401; khong duoc match them.
- User restricted khi queue: RPC doc pool moi lan find; job moderation can cancel
  ticket waiting dang ton tai.
- Time control sai: RPC va API validate.

======================================================================
H. TELEMETRY VA MONITORING
======================================================================

Da tao:
- matchmaking_events.
- matchmaking_claim_logs.
- matchmaking_abuse_logs.
- matchmaking_metrics_hourly view.

Metric uu tien:
- p50/p95/p99 wait time theo mode/pool/time control.
- match_success_rate va queue_cancel_rate.
- stale_ticket_count.
- claim_failure_rate va active-game conflict.
- average/p95 rating_gap.
- RPC latency va DB lock wait time (lay tu Supabase/observability).
- heartbeat miss va reconnect-after-match.

Alert de xuat ban dau:
- p95 wait rapid/blitz > 20 giay trong 10 phut.
- stale ticket > 10% active queue.
- RPC error > 1% request trong 5 phut.
- active-game conflict/duplicate prevention tang dot bien.
- p95 rating gap > 350 o pool standard.

Trace ho tro customer support:
1. Tim session_id/client_id trong matchmaking_events.
2. Tim ticket id.
3. Tim claim logs va game id.
4. Kiem tra presence transition va game status.
5. Kiem tra event realtime/API response theo timestamp.

======================================================================
I. API BACKEND
======================================================================

POST /api/online/matchmaking/find
- Auth: Firebase cookie; user/rating lay server-side.
- Body: timeControl, clientId, sessionId, region, ratingRangePreference.
- DB: quick_match_find_game RPC.
- Response: waiting hoac matched, ticketId/window/gap/game.
- Rate limit: 30/phut.

POST /api/online/matchmaking/cancel
- Body: reason.
- DB: quick_match_cancel RPC.
- Response: cancelled va online summary.
- Cancel spam tao cooldown o DB.

GET /api/online/matchmaking/status
- Doc active game hoac ticket active cua chinh user.
- Dung cho reconnect/recovery, khong cho doc queue cua nguoi khac.

POST /api/online/heartbeat
- Cap nhat last_seen ticket/presence; khong sua joined_at.
- Khong phai duong primary de truyen nuoc di.

GET /api/online/games/:id
- Chi hai player trong game moi doc duoc.

RLS:
- Bang matchmaking bat RLS, client khong truy cap truc tiep.
- Next.js backend dung service role; RPC chi grant execute cho service_role.

- Mark waiting/claimed ticket stale neu heartbeat het 30 giay.
- Sua presence queue khong con ticket active ve online.
- Xoa active lock khong con game active.
- Ghi maintenance event.

Can them job:
- Moi 5 phut: aggregate dashboard metrics tu matchmaking_metrics_hourly.
- Moi 5-15 phut: detect cancel/abort/disconnect pattern va ghi abuse log.
- Moi gio: recompute trust score co versioned rule.
- Hang ngay: audit active-game conflict va rating anomaly.

Tat ca job can idempotent; neu chay hai instance, update co condition status va
row lock/transaction de khong xu ly trung.

N. BO SUNG NANG CAP 9/10 - LAN TIEP THEO
======================================================================

Da bo sung vao code/schema:

1. Idempotency va anti multi-tab
- online_match_queue.idempotency_key.
- unique partial index (user_id, idempotency_key) cho ticket waiting/claimed.
- Frontend giu queue attempt id trong sessionStorage, clear khi matched/cancelled.
- API truyen p_idempotency_key vao quick_match_find_game.

2. FIFO cong bang hon
- Opponent query uu tien q.joined_at truoc rating gap trong tap ung vien hop le.
- Rating window van chan match qua lech rating.
- Recent opponent avoidance 30 phut, mo khoa khi mot ben cho > 20 giay.

3. Fairness scoring va audit
- online_games.fairness_score, match_region, matchmaking_correlation_id.
- matchmaking_fairness_score(wait_ms, rating_gap, same_region, recent_opponent).
- matchmaking_events.correlation_id.
- API ghi event api_find_completed gom duration_ms, status, idempotency_key.

4. Heartbeat an toan hon
- quick_match_heartbeat RPC cap nhat last_seen ticket va presence.
- Backend heartbeat khong update online_match_queue truc tiep nua.

5. Rating finalize atomic
- finalize_online_rating_result(game_id, result) lock game + lock rating users theo thu tu.
- online_rating_events van la idempotency primary key cho rating result.
- applyOnlineRatingResult goi RPC truoc, fallback JS cu neu migration chua apply.
- deviation giam dan sau moi game, provisional tat sau 20 game.

6. Trust score schema day du hon
- resign_too_early_rate.
- engine_similarity_score.
- suspicious_pattern_score.
- account_age_days.
- verified.
- games_played.
- policy_version.
